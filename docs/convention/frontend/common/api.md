# Frontend API Convention

백엔드 응답 형식은 [공통 API 컨벤션](../../backend/common/api.md)을 따른다.

## 1. 경계

- API 호출과 응답 변환은 화면 컴포넌트 밖에 둔다. 컴포넌트는 HTTP 상태 코드나 응답 본문 구조를 직접 해석하지 않는다.
- 응답 데이터는 외부 입력으로 취급한다. 중요한 경계에서는 런타임 검증을 하고, OpenAPI 타입을 생성할 수 있으면 수기 중복 타입보다 생성 타입을 우선한다.
- 로딩, 빈 결과, 오류 상태를 화면에서 각각 처리한다.

## 2. 오류

- `application/problem+json` 응답의 `code`로 분기한다. `detail`은 사용자에게 보여줄 메시지로 사용한다.
- 예상하지 못한 오류에는 공통 메시지를 보여주고 `requestId`를 확인할 수 있게 한다.
- `401` 인증 실패와 `403` 권한 부족을 구분한다. 토큰·비밀번호·개인정보는 브라우저 로그에 남기지 않는다.

## 3. 데이터 관리

- 동일한 서버 응답을 여러 상태 저장소에 복제하지 않는다.
- 인증 방식과 재시도 정책은 프로젝트에서 정한다. 변경 요청은 무조건 자동 재시도하지 않는다.
