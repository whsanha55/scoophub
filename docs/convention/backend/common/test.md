# Test Convention (Backend 공통)

언어와 무관한 백엔드 테스트 규칙이다. 도구와 작성법은 언어별 `test.md`를 따른다.

## 1. E2E 테스트

- API를 추가하거나 기존 API의 동작을 바꾸면 E2E 테스트 파일을 함께 작성한다.
- 실제 애플리케이션을 띄우고 HTTP 요청부터 DB 반영까지 검증한다. 내부 의존성을 mock으로 바꾸지 않는다.
- DB, 메시지 브로커 같은 인프라는 Testcontainers로 띄운다. 제3자 외부 API만 스텁 서버로 대체한다.
- 성공 흐름과 대표 실패(인증 실패, 검증 오류)를 검증한다. 세부 분기는 단위 테스트에서 검증한다.
- 일반 테스트와 분리해 따로 실행할 수 있게 둔다 (예: Gradle `e2eTest` 소스셋, Go `//go:build e2e` 태그).
- 파일은 리소스 단위로 만든다: `OrderE2ETest.kt`, `order_e2e_test.go`.
- 테스트끼리 데이터를 공유하지 않는다. 각 테스트가 필요한 데이터를 직접 만든다.
