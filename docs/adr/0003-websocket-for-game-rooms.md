# 게임 방 통신은 순수 WebSocket 하나로 통일한다

방에 들어간 뒤 오가는 모든 메시지(수, 채팅, 시계, 입·퇴장, 실시간 상태)는 방마다 WebSocket 연결 하나로 주고받는다. 메시지는 JSON(`{type, payload}`)이다. 방 만들기와 초대코드 확인처럼 한 번 묻고 끝나는 요청은 REST로 남긴다. 턴제만 보면 SSE로 충분하지만, 나중에 레몬게임 다인 대결이나 뱀파이어 서바이벌 같은 실시간 게임을 올릴 계획이 있다. 그때 전송 방식이 두 벌이 되지 않도록 처음부터 WebSocket을 쓴다.

## Considered Options

- **SSE + REST POST**: 턴제에는 충분하고 재접속이 자동이지만, 실시간 액션 게임을 감당하지 못한다.
- **STOMP**: 구독 모델이라 채팅에는 편하지만, 메시지가 잦은 실시간 게임에서는 오버헤드와 제약이 생긴다.

## Consequences

- 운영 경로는 Cloudflare → Caddy → 백엔드다. `/ws*`는 Next 프록시를 거치지 않는다. Caddyfile에서 `/docs`처럼 백엔드(20010)로 직접 보내야 한다.
- Cloudflare는 일정 시간 동안 메시지가 없는 WebSocket을 끊는다. 서버가 주기적으로 ping을 보내 연결을 유지한다.
- 재접속은 클라이언트가 직접 처리한다. 다시 붙을 때 게스트 ID 토큰으로 자기 자리를 되찾는다.
