# 차례 안의 중간 행동은 game_action 으로 중계·보관하고, 주사위는 굴리는 클라이언트가 만든다

야추다이스는 한 차례 안에 굴림·고정 같은 중간 행동이 여러 번 있고, 점수표 칸에 기록해야 차례가 넘어간다. 기존 `move` 는 보낼 때마다 차례가 바뀌고 시계가 멈추므로 중간 행동을 실을 수 없다. 그래서 세 가지를 함께 정한다.

1. **중계**: WS 메시지 `game_action` 을 추가한다. 대국 중 **차례인 대국자**만 보낼 수 있고, 서버는 payload 를 해석하지 않고 `{side, action}` 으로 방 전체에 중계한다. 차례와 시계는 바뀌지 않는다. 차례를 마감하는 행동(야추의 기록)은 기존 `move` 를 쓴다.
2. **행동 로그**: 직전 `move` 이후의 `game_action` 을 방에 보관하고(최근 64개) 방 스냅샷의 `actions` 로 내려준다. `move`·대국 시작·재대국 때 비운다. 대국자가 새로고침해도 자기 차례의 주사위와 남은 굴림 횟수가 돌아오고, 새로고침으로 굴림 횟수를 되돌리는 치팅이 막힌다. 서버는 여전히 게임 규칙을 모른다(ADR-0001).
3. **주사위 무작위성**: 주사위 값은 굴리는 클라이언트가 `crypto.getRandomValues` 로 만들어 `game_action` 에 싣는다.

## Considered Options

- **서버가 주사위를 굴린다**: 조작을 막을 수 있지만 서버가 게임 규칙(고정한 주사위, 굴림 횟수)을 알아야 해 ADR-0001 의 "서버는 규칙을 모른다"가 깨진다. 게임마다 서버 코드가 늘어난다.
- **커밋-공개(commit-reveal) 방식**: 양쪽이 난수를 섞어 조작을 막는다. 메시지 왕복이 늘고 끊김·재접속 처리가 복잡해진다.
- **행동 로그 없이 중계만**: 구현은 가장 작지만, 새로고침하면 진행 중인 차례를 잃고 굴림 횟수를 리셋할 수 있다.
- **관전자도 game_action 을 보낼 수 있게**: 쓰임새가 없고, 관전자나 상대가 보낸 행동이 로그에 섞이면 재접속 복구가 오염된다.

## Consequences

- **재현 불가능한 신뢰를 받아들인다.** 체스·장기·오목은 상대 클라이언트가 기보를 다시 두어 합법수인지 검증할 수 있다. 주사위 값은 그럴 수 없어서, 조작된 클라이언트가 원하는 눈을 보내면 막을 방법이 없다. 이 서비스는 지인끼리 두는 개인용이라 이 위험을 받아들인다. 공개 대전이나 순위를 붙이면 서버 굴림이나 커밋-공개로 바꿔야 한다.
- 클라이언트는 행동 로그를 재생할 때 고정한 주사위의 값은 이전 값을 유지하고 굴림은 3회까지만 반영해, 조작된 행동 일부를 무시한다.
- 기록(`move`)의 점수는 기록한 클라이언트가 계산해 `to` 에 싣는다. 행동 로그가 비워져 지난 차례 주사위로 다시 계산할 수 없기 때문이다.
- payload 는 직렬화 1,024자를 넘으면 거절해 방 메모리를 지킨다.
